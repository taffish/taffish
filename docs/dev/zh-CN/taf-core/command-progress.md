# 命令状态与进度

面向用户的慢操作通过 **stderr** 提示当前状态，最终结果仍写入 stdout，无需额外参数。

| 命令 | 提示内容 |
| --- | --- |
| `taf update` | 下载或读取索引，随后检查并保存。 |
| `taf install`、`taf upgrade` | 当前需要变更的目标，以及源码获取、命令构建和验证阶段。 |
| `taf install --repair` | 初次扫描、取得写锁后的计划复核，以及每个目标的获取、构建、验证和安装切换。 |
| `taf prune`、`taf uninstall` | 检查候选项、删除选定的已安装版本。预览不会声称正在删除。 |
| `taf publish` | 仓库、保护策略、提交、分支、标签、Release 的检查，已有查询的重试，以及写入后的确认。dry-run 不会声称正在执行发布步骤。 |
| `taf build` | 操作已耗时约一秒后，在快照、命令入口和验证阶段显示提示。镜像构建保留后端自己的输出。 |

## 如何理解显示

例如 `正在获取源码 | taf-example-v1.0.0-r1 | 2/5` 表示**正在处理第 2 个目标**，
并不表示已有两个成功，也不是耗时已完成 40%。实际结果以命令最终摘要为准。
依赖项工作可能包含在父目标的计数中。

stderr 连接交互终端时，短且字宽可确定的提示原地更新。正常结果或流式子进程输出前，
以及成功、失败退出时，状态行都会换行收尾。重定向或 `TERM=dumb` 使用普通文本行。
日志会抑制短时间内重复的阶段；目标改变或明确的查询重试可以立即输出一行。
过长或字宽无法确定的文本也降级为普通行，不使用光标控制。状态行的标签和目标会限长、
清理控制字符，命令结果仍保留完整身份信息。
显示预算最多为 78 列；`COLUMNS` 指定更小宽度时进一步收窄。不查询或持续跟踪终端窗口大小。

提示在**操作边界**更新，不使用后台计时线程。一次同步下载、文件操作或远端查询
耗时较长时，同一个阶段会保留到该操作返回。不会伪造百分比、预计完成时间、超时或
心跳保证；看到阶段提示不代表远端操作已经成功。Git、容器后端仍可能输出自己的细节。

## 不变的接口与行为

- JSON、MCP 不输出这些提示。顶层 core 调用使用 `:verbose nil` 时保持静默。
  嵌套的静默 helper 可以共享外层人类调用的状态显示，但不打印自己的正常结果摘要。
- 快速查询、编译生成的 shell、`taf run` 和 app stdout 不增加进度装饰。
  处理命令结果时，不要把 stderr 合并进 stdout。
- 状态输出失败只关闭状态显示，不改变原操作结果。
- 状态提示不决定重试、超时、校验、锁、修复、删除或发布续跑；原有安全检查保持不变。
- 内置英文、中文共用已有语言设置。外置 `messages.json` 可覆盖 `taf.progress.*`
  消息键，缺少的条目按已有语言规则回退。不新增配置或机器输出 schema。

内部实现位于 `taf-core/progress.lisp`，不导出新 API，复用已有 host 终端检测和保守
显示宽度计算。离线二进制覆盖见[外部测试说明](../../../../test/README.md)。
