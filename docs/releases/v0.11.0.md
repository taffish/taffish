# TAFFISH v0.11.0 Release Notes

TAFFISH v0.11.0 is a feature release focused on operational reliability,
diagnostics, localization, and cross-platform delivery. It retains the existing
parameter semantics and taf-app command model while strengthening project
creation, diagnosis, builds, publishing, and automation. Intentional changes to
inline-call boundaries and publish policy are described under Compatibility.

Complete installation and usage documentation is in the repository
[README](../../README.md).

As of 2026-11-07, v0.11.0 is a local release candidate. The final commit, its
four CI jobs, the tag and Release, and public GitHub/Gitee installation checks
are pending. See [Validation](#validation) for results by platform.

## 2026-10-23 Source Corrections Before Release

The source candidate now handles SPACE/TAB separators consistently when adding
or recognizing the first `--compile` option in an inline child command. It also
preserves full-line source comments without interpreting closed, empty, or
unclosed inline markers as child steps. Source classification still controls
inline structure; substituted data does not create source comments. Ordinary
code followed by a shell comment remains outside this full-line rule. The four
argument paths and child-precompilation timing retain their existing contracts.

Regression checks cover generated shell, dependency discovery, project wrappers,
and MCP compilation. The source-repair work initially left the version, formal
`target/` binaries, checksums, and signatures unchanged. The maintainer has since
rebuilt and signed the formal payloads; their current hashes are recorded under
[Release Verification](#release-verification). The 2026-10-12 results and hashes
remain historical evidence for the earlier candidate and do **not** validate
these later corrections.

The MCP specification now documents existing local write tools and dry-run
defaults without adding capabilities. The README also records the current
macOS payloads' declared minimum OS, macOS 15.0; this is metadata evidence, not
a new test on older systems.

## Highlights

### Command Status During Slow Operations

- Human stderr reports download, source retrieval, build/validation, repair,
  removal and publish stages, with target counts where known.
- Short TTY notices update in place; logs are rate-limited. JSON/MCP and
  execution decisions remain unchanged. Updates are event-driven, not a
  background heartbeat or an estimated completion time.

### Native Multi-Platform App Image Workflows

- `taf new --docker` generates a declaration-driven GitHub Actions workflow.
- Declared `linux/amd64` and `linux/arm64` platforms build independently on
  matching native GitHub-hosted runners instead of using QEMU for ARM64.
- The workflow validates project metadata and source identity before building,
  keeps platform caches independent, and publishes the final manifest only from
  validated per-platform results.
- Manual dispatch can rebuild a selected platform subset without rebuilding an
  already successful platform unnecessarily.

### Read-Only-First Environment Diagnostics

- `taf doctor` diagnoses TAFFISH homes, config, index state, command paths,
  Bash/Zsh/Fish completion, Vim/Neovim integration, Apptainer SIF cache policy,
  and Docker/Podman/Apptainer readiness.
- Concise text, `--verbose`, shell-specific guidance, and stable
  `taffish.doctor/v1` JSON output are available.
- Ordinary diagnostics remain read-only. Only explicit `--init` creates
  TAFFISH-owned directories; doctor does not edit shell/editor files, change
  permissions, start services, pull images, or run containers.

### Consistent Hub Maintenance And Installation Diagnostics

- Batch installation and upgrade use the local index's `latest` target. A shared
  comparator handles numeric and mixed versions such as `a.7.10` versus `a.7.3`,
  while preserving protection against automatic downgrades.
- Prune retains an installed, verified, same-source index latest and removes
  only reliably older versions. Missing targets, private or unknown sources,
  newer versions, and unverified installations remain protected.
- `taf doctor index` checks the cached index; `taf doctor hub [APP|COMMAND...]`
  checks installed metadata, frozen files, manifests, paths, and command aliases.
  Both are offline and read-only, with targeted recovery advice and JSON output.
- Legacy installations without a build manifest are reported as `unverified`,
  not automatically treated as damaged. Selected invalid or unknown installations
  block batch writes; local consistency does not establish official authenticity.
- `outdated` and `upgrade` filter app kinds before validation and version-order
  checks. Problems in excluded flows cannot block tool-only plans, or vice versa;
  selected packages retain their checks. MCP planners share these protections.

### Quieter Hub Output And Explicit Repair

- Default repeated diagnostics are grouped by issue type and recovery policy,
  with counts and at most three examples per group. `--verbose` and JSON retain
  full evidence; maintenance no longer repeats skipped rows after the summary.
- `doctor hub` reuses batched read-only probes for faster full/targeted scans
  without skipping checksum checks. Human stderr shows in-place TTY stages/counts
  or rate-limited log lines; JSON/MCP remain free of progress text.
- Shared field layout uses conservative Unicode display widths, with separate
  lines for long or complex text rather than language-specific padding.
- Explicit `install --repair` supports exact targets and two batch selectors:
  `--all` retains installed index.latest selection; `--all-installed` includes
  every local installed version, including historical versions. Both default
  to preview and require `--yes` to apply, with scope/kind filters. Repair never
  installs missing versions/dependencies, upgrades or prunes; verified targets
  are skipped. Unreadable and unindexed installations remain visible as blocked.
- Doctor separates enumerated totals from affected app/version and issue counts.
  Repair output identifies its selection scope and gives a matching apply command.
- Repair rejects `--force`, `--from` and `--prune-old`. Complete read-only
  preflight blocks all batch writes if any target is blocked. Rebuilds require
  matching source/identity, safe paths and a fixed commit; unknown schemas,
  private sources and custom launchers are rejected, not covered by invented manifests.
- Repair uses backups, staging, validation and rollback on failure. Interrupted
  runs retain journals and block blind retries. It does not promise whole-batch
  atomicity, crash durability, automatic crash recovery or zero downtime.
  Repair and normal install/uninstall/prune share cooperative home/bin write
  locks without changing deletion policy; older clients need not honor them.
- No MCP repair tool, parameter or execution entry is added. Existing MCP write
  capabilities are unchanged; diagnostic and maintenance-planner safety remains
  intact. See the [repair contract](../dev/en/taf-core/hub-maintenance.md#explicit-repair).

### Resumable, Conflict-Safe Publishing

- Publication no longer requires a version newer than earlier remote tags.
  New immutable identities, including older maintenance branches and upstream
  versions such as `2.0.0-a.7.10-r1`, are admitted independently of sorting.
- With `--release`, the default/`--latest` creates a formal GitHub Release
  marked Latest; `--pre` creates a GitHub prerelease without setting Latest;
  new `--no-latest` creates a formal Release without setting Latest.
  These flags are mutually exclusive. Without `--release`, publishing stays
  tag-only and does not change GitHub Latest.
- `taf publish` now reconciles repository, policy, commit, branch, local tag,
  remote tag, and optional GitHub Release stages before changing remote state.
- After a network or process interruption, running the same publish command
  again continues a matching partial publication and skips completed stages.
- Matching completed publications become successful no-ops. Conflicting
  commits, tags, release notes, repository state, or publish intent stop with an
  error instead of being overwritten.
- Release creation verifies that its tag is already remote. Resuming checks
  title, notes, draft/prerelease state, and journal intent; an incomplete
  response is not assumed to describe a matching formal Release.
- Rerunning a completed publication does not reclaim Latest from a subsequent
  Release. Rejected channel changes preserve the original journal intent;
  legacy journals remain readable and cannot bypass remote identity checks.
- Repository creation tolerates the short GitHub visibility delay after
  `--create-repo`, and newly created repositories retain the existing secure
  immutable-release/tag-protection policy unless explicitly disabled.

### Idempotent Project Builds

- Versioned command wrappers and frozen source snapshots include an internal
  build manifest describing source and artifact identity.
- Repeating `taf build` verifies and reuses an exact valid artifact instead of
  rewriting it.
- Missing, stale, damaged, or extra snapshot content triggers an exact staged
  rebuild, with replacement only after the new artifact validates.
- Final wrapper installation uses an exact pathname for both dotted and
  dotless version strings, and safely cleans or restores interrupted staging
  residue within the same artifact.
- `taf publish --build` participates in the same identity and recovery model,
  preventing duplicate snapshot files during resumed publication.

### Built-In English And Chinese

- `taf`, `taffish`, and `taffish-mcp` human help use the shared localization
  layer with built-in English (`en`) and Chinese (`zh`).
- Human CLI output defaults to `auto`, follows a recognized host locale, and
  falls back deterministically to English.
- `taf config language` discovers languages and shows the active selection;
  `taf config language en|zh|auto` persists a preference for user or system
  scope. `TAFFISH_LANGUAGE` provides a one-command override.
- Advanced users can provide sparse external locale packs. Invalid or missing
  entries fall back safely without changing command names, generated shell,
  JSON schemas, MCP protocol data, index data, or other machine interfaces.
- Top-level `taf` and `taffish` help provides concise command/input guidance,
  examples, language selection, and website/Hub/support links. Container settings
  precede compiler examples and list the accepted backend values. Subcommand
  help stays separate, and version output remains a single line.
- Both built-in languages work immediately after installation without a locale
  download. Choosing GitHub or Gitee does not select the CLI language; ordinary
  reinstalls preserve saved preferences. The standalone installer stays English.

### Verified, Transactional Binary Installer

- GitHub and Gitee installers are generated from one canonical POSIX `sh`
  template, with CI drift, syntax, and ShellCheck gates.
- For official raw downloads, the default `auto` mode requires every selected
  binary to match `SHA256SUMS`. When the detached signature, release public key,
  `gpg`, and `gpgv` are all available, it also verifies the signature against
  the pinned TAFFISH key fingerprint. If the default signature or key cannot
  be fetched, or either tool is missing, the installer records `sha256`.
  A failed signature or fingerprint check stops installation.
- Archive paths and entry types are checked before extraction. Downloads have
  bounded retry and connection timeout controls.
- Candidate binaries pass `--version` smoke tests before a locked,
  transactional three-command replacement. Interrupted commits restore the
  previous binaries and install receipt; identical reinstalls do not replace
  unchanged core binaries.
- System installs create a missing Apptainer SIF directory as
  administrator-managed `0755` and preserve an existing mode by default.
  `--shared-sif-cache` explicitly applies and verifies sticky `1777` only on
  the exact SIF directory.
- `--dry-run` resolves the plan without network or writes, and successful
  installs record non-secret asset hashes and actual verification level in
  `install-receipt.toml`.

### Argument And Inline-Call Corrections

- Empty CLI values are accepted without a lexer bounds error; a missing option
  value remains an error. This does not add quoting to raw-text parameters.
- For source-compiled `<taffish>` lines, only source text determines the start
  and end of `[[taf: ...]]`. Substituted quotes and delimiter-looking data no
  longer change those boundaries; source quotes and escapes protect `]]`.
- Child-compilation failure diagnostics are shell-quoted separately, preventing
  the error message from evaluating the command text again.
- `taf check/build` share the source-boundary scanner for dependency discovery
  without binding parameters or running apps. Other emitters and the four
  parameter paths retain their existing behavior.

See [Argument Passing](../standards/en/argument-passing.md) for forwarding,
display, empty-value and delayed-variable examples, and the
[emitter design](../dev/en/taffish-core/builtin-taffish.md#design-boundaries-and-tradeoffs)
for implementation boundaries and retained limitations.

### Portability And Test Hardening

- Standard-input terminal detection is implemented by `han.host` for SBCL and
  LispWorks, preserving pipe/file stdin for delivered `taf run` binaries while
  avoiding accidental terminal blocking.
- External tests isolate HOME, XDG, TAFFISH homes, Git configuration, locale,
  temporary directories, and runtime backend variables.
- `taf check` rejects only the exact scaffold smoke placeholders `TODO` and
  `TODO --help`; valid command names containing `todo` remain accepted.
- Project and configuration diagnostics use portable real line breaks across
  SBCL and LispWorks instead of implementation-dependent escape assumptions.
- CLI entry-point error handling now includes runtime I/O and language
  initialization. Failed error reporting still exits unsuccessfully without
  using stdout as a fallback, including in MCP stdio mode.
- SBCL SIGINT produces a short diagnostic instead of a runtime backtrace,
  retaining exit status 1. LispWorks retains its fixed `Interrupted - quitting`
  stdout notification on SIGINT; global signal handlers and SIGTERM behavior
  are unchanged. This does not promise recovery from native crashes or resource
  exhaustion, or change library condition handling.
- The delivered-binary suite covers compiler behavior, concurrent temporary
  files, project build/publish recovery, Hub package maintenance, diagnostics,
  localization, a long-lived MCP stdio session, and CLI error boundaries.
  Error-boundary probes keep a controlling terminal and a timeout, and use
  read-only descriptors and broken pipes to test write failures reliably.

## Compatibility

v0.11.0 preserves existing command interfaces, with the explicit inline-boundary
and publish-policy changes noted below.

- Ordinary parameters remain raw text; supplied `@:` block tokens retain
  per-token POSIX shell encoding. `*ARGV*` and taf-app command mode remain
  space-joined shell text. `"::*ARGV*::"` keeps its joined-string display behavior;
  it is not transparent argv forwarding. Existing delayed-variable shell-text
  uses remain supported. Block-token encoding already existed in v0.10.1.
- Source-backed inline calls now take their delimiters only from source.
  Assembling a complete `[[taf: ...]]` through parameter substitution no longer
  creates an inline call on that path. Put delimiters in source and substitute
  only the contents. Legacy emitter callers with only `:line/:number`, including
  dynamic `<taf-app:taffish>` command mode, retain text-based boundary scanning.
  Prefix checks, `--compile` handling and child-precompilation timing are unchanged.
- Inline calls remain single-line; this is not a full shell parser or automatic
  sanitization of substituted shell text. Parent/child flows retain the contract
  of each parameter path; a child using raw text can still lose argv boundaries.
- Existing `taf` commands and taf-app wrapper command lines remain supported;
  the new diagnostic and language options are additive.
- Machine-readable JSON keys/values, MCP tools/resources/prompts/results,
  history/index/config data, command and option tokens, and external process
  output remain language-invariant.
- Publishing remains GitHub-only. GitHub/Gitee/custom source rewrites continue
  to apply to index and installation paths, not publication.
- Publish no longer enforces increasing version order. `--pre` now requests an
  actual GitHub prerelease, rather than merely bypassing the old ordering gate.
  Default/`--latest` explicitly promotes a newly created formal Release;
  maintenance releases that must not replace Latest should use `--no-latest`.
  Existing tag identities remain protected. Installation still consumes the
  index's `latest` rather than deriving it from GitHub Release flags.
- Official prebuilt targets remain macOS Apple Silicon and glibc-based Linux
  x86_64.

## Install This Release

These commands apply once the v0.11.0 tag payloads are available from the selected
provider. This documentation closeout does not verify those publication paths.


Verify checksums:

```sh
cd target
shasum -a 256 -c SHA256SUMS
```

Verify the checksum signature:

```sh
gpg --import TAFFISH-RELEASE-KEY.asc
gpg --verify SHA256SUMS.asc SHA256SUMS
```

Before trusting the key, compare its fingerprint with:

```text
F863 33E6 0BD6 74F1 59A5  651A B919 3F30 C424 7BB2
```

After publication, use `target/SHA256SUMS` from the `v0.11.0` tag.
`--verify sha256` requires the manifest and matching hashes for the selected
binaries. To require the signed manifest as well, use `--verify gpg`. This
mode stops if the detached signature, release public key, `gpg`, or `gpgv` is
missing, or if verification fails.

Payload checks do not independently authenticate an installer fetched through
`curl | sh`. High-security bootstrap should first obtain and inspect a
fixed-tag installer or release bundle through an independently trusted channel,
manually verify the materials above, and then run the installer locally.

## Supply-Chain Status

This release provides public Apache-2.0 source, immutable tag/release policy,
six versioned binaries, SHA256 checksums, a GPG-signed manifest, release-key
fingerprint publication, CI checks, cross-platform delivered-binary tests, and
install-time source commit verification when the Hub index supplies
`source.commit`.

This release does not claim GitHub Actions artifact attestation for the core
binaries, SLSA provenance, reproducible builds, or SBOM coverage.
Linux/LispWorks binaries remain a manual maintainer build because LispWorks is
a commercial implementation.
