# TAFFISH v0.11.0 Release Notes

TAFFISH v0.11.0 是一个以运行可靠性、环境诊断、多语言和跨平台交付为重点的 feature
release。它保留既有参数语义和 taf-app 命令模型，同时加强项目创建、诊断、构建、发布和
自动化能力。内联调用边界和发布策略的有意变化见兼容性说明。

完整安装和使用说明见仓库根目录的 [README-CN](../../README-CN.md)。

截至 2026-11-07，v0.11.0 仍是本地发布候选。最终提交及其四项 CI、tag 和 Release、
GitHub/Gitee 线上安装验证均待完成。各平台的核对结果见[验证情况](#验证情况)。

## 2026-10-23 发布前源码修正

当前源码候选在添加或识别内联子命令首个 `--compile` 选项时统一处理 SPACE/TAB
分隔符；完整源码注释行原样保留，其中已闭合、空内容或未闭合的内联标记不再被当作
子步骤。源码分类仍然决定内联结构，替换值不会创建源码注释；普通代码后的尾部 shell
注释不属于这条完整行规则。四种参数路径和子命令预编译时机保留原有契约。

回归检查覆盖生成 shell、依赖发现、项目 wrapper 和 MCP 编译。源码修复阶段没有修改
版本、正式 `target/` 二进制、校验和及签名；此后维护者已完成正式载荷重建和签名，
当前摘要见[Release 校验](#release-校验)。2026-10-12 的结果与哈希继续作为旧候选的
历史证据保留，**不能用于验收这些后续修正**。

MCP 规范同步说明既有本地写工具及 dry-run 默认值，没有增加能力；README 补充了当前
macOS 载荷声明的最低系统 macOS 15.0，这是元数据证据，不是新增的旧系统实测。

## 重点更新

### 慢操作阶段提示

- 人类 stderr 提示下载、源码获取、构建验证、修复、删除和发布阶段；总数已知时显示目标计数。
- 短提示在 TTY 原地更新，日志限频。JSON/MCP 和执行决策保持不变。
  提示由操作边界触发，不是后台心跳或预计完成时间。

### 原生多平台 App 镜像工作流

- `taf new --docker` 会生成声明驱动的 GitHub Actions workflow。
- 声明的 `linux/amd64` 和 `linux/arm64` 平台会在匹配的 GitHub-hosted 原生 runner 上
  独立构建，不再使用 QEMU 构建 ARM64。
- workflow 在构建前校验项目元数据和源码身份，为不同平台使用独立 cache，并且只根据
  已校验的平台结果发布最终 manifest。
- 手动触发时可以只重建指定平台，不必重复构建已经成功的平台。

### 只读优先的环境诊断

- `taf doctor` 可以诊断 TAFFISH home、config、index、命令路径、Bash/Zsh/Fish
  completion、Vim/Neovim、Apptainer SIF cache 策略以及 Docker/Podman/Apptainer
  readiness。
- 支持简洁文本、`--verbose`、指定 shell 的建议，以及稳定的
  `taffish.doctor/v1` JSON 输出。
- 普通诊断保持只读。只有显式 `--init` 才创建 TAFFISH 自有目录；doctor 不修改
  shell/editor 文件或权限，不启动服务，不拉取镜像，也不运行容器。

### 一致的 Hub 维护与安装诊断

- 批量安装和升级以本地 index 的 `latest` 为目标；统一比较器正确处理纯数字版本及
  `a.7.10`、`a.7.3` 这类混合版本，同时保留禁止自动降级的保护。
- prune 保留已安装、已验证、同源的 index latest，只移除可靠判定为更旧的版本。
  目标缺失、私有或未知来源、较新版本及未验证安装均保持受保护。
- `taf doctor index` 检查缓存索引；`taf doctor hub [APP|COMMAND...]` 检查安装元数据、
  冻结文件、构建清单、路径和命令快捷入口。两者离线只读，提供具体处理建议和 JSON 输出。
- 旧安装缺少构建清单时报告 `unverified`，不直接判为损坏。选中范围内的损坏或无法确认
  状态会阻止批量写入；本地文件一致性不代表官方来源认证。
- `outdated` 和 `upgrade` 先按应用类型筛选，再验证和比较版本。被排除的 flow 不会
  阻断仅针对 tool 的计划，反向也一样；选中对象仍执行原有检查。MCP 规划工具同样适用。

### 更简洁的 Hub 输出与显式修复

- 默认重复诊断按问题类型和处理策略汇总，包含计数及每组至多三个例子；`--verbose` 和
  JSON 保留完整证据，维护摘要后不再逐行列出跳过的应用。
- `doctor hub` 复用批量只读探测，加快全量/定向扫描但不省略摘要校验。人类 stderr
  显示阶段/计数，TTY 原地更新、日志限频；JSON/MCP 无进度文字。
- 共享字段排版采用保守 Unicode 显示宽度，长或复杂文本分行，不按语言补空格。
- 显式 `install --repair` 支持精确目标与两种批量选择：`--all` 保留已安装 index.latest
  的选择逻辑；`--all-installed` 选择本地全部已安装版本，包含历史版本。两者默认预览，
  加 `--yes` 才执行，并支持作用域/类型筛选。不新装版本或依赖、不升级、不清理；
  已验证目标跳过，不可读或未被索引的安装保留为受阻目标。
- doctor 区分已枚举总量、涉及问题的应用/版本数和问题项数；修复摘要明确选择范围，
  确认执行命令与当前选择器、作用域、类型保持一致。
- 修复拒绝与 `--force`、`--from`、`--prune-old` 组合。整批先完成只读预检，任一
  目标不符合安全条件时整批不写入。只有来源、身份一致，路径安全且 commit 固定才可重建；
  未知元数据格式、私有来源、自定义命令入口拒绝覆盖，不伪造清单。
- 修复采用备份、暂存、验证及失败回滚；运行中断保留事务日志，阻止盲目重试。
  不承诺整批原子性、断电后的持久性、崩溃自动恢复或零停机。修复与普通
  install/uninstall/prune 共用 home/bin 协作写锁，不改删除策略，不保证旧客户端遵守新锁。
- 不新增 MCP 修复工具、参数或执行入口；既有 MCP 写能力不变，诊断与维护计划工具
  的安全边界保留。详见[修复约定](../dev/zh-CN/taf-core/hub-maintenance.md#显式修复)。

### 可续跑且拒绝冲突的发布

- 发布不再要求当前版本高于远端历史 tag。旧维护分支和 `2.0.0-a.7.10-r1` 这样的
  上游版本，只要是无身份冲突的新发布，就不因版本排序而被拒绝。
- 带 `--release` 时，默认/`--latest` 创建正式 GitHub Release 并标记为 Latest；
  `--pre` 创建 GitHub prerelease 且不设置 Latest；新增 `--no-latest` 创建正式
  Release 但不设置 Latest。三个渠道选项互斥。不带 `--release` 仍然只发布 tag，
  不改变 GitHub Latest。
- `taf publish` 会先协调 repository、policy、commit、branch、local tag、remote tag
  和可选 GitHub Release 的状态，再修改远端。
- 网络或进程中断后，重新运行同一条 publish 命令会继续匹配的半完成发布，并跳过已经
  完成的阶段。
- 已经完整匹配的发布会成为成功 no-op；commit、tag、release notes、repository 状态或
  publish intent 冲突时会停止，而不是覆盖不可变对象。
- Release 创建会确认 tag 已在远端；续跑检查标题、正文、draft/prerelease 状态和
  journal 意图，不会把不完整响应当作匹配的正式 Release。
- 重跑已完成发布不会从后续 Release 抢回 Latest。错误渠道重试不会污染原始续跑意图；
  旧 journal 仍可读取，但不能绕过远端身份检查。
- 使用 `--create-repo` 后会容忍 GitHub 新仓库的短暂可见性延迟；新建仓库仍默认启用既有
  immutable release 和 tag 保护策略，除非用户显式跳过。

### 幂等项目构建

- 带版本 command wrapper 和冻结源码 snapshot 使用内部 build manifest 记录源码和
  artifact identity。
- 重复执行 `taf build` 时会校验并复用完全匹配的有效产物，不再无条件重写。
- snapshot 缺失、过期、损坏或含多余内容时，会在 staging 中精确重建，并只在新产物
  校验通过后替换旧产物。
- 带点或不带点的版本字符串都会安装到精确 wrapper pathname，并在同一 artifact 边界内
  安全清理或恢复中断事务残留。
- `taf publish --build` 使用相同 identity 和恢复模型，避免续跑发布时生成重复 snapshot
  文件。

### 内置英文和中文

- `taf`、`taffish` 和 `taffish-mcp` 的人类 help 使用共享语言层，并内置英文（`en`）和
  中文（`zh`）。
- CLI 人类输出默认使用 `auto`，跟随可识别的主机 locale，并确定性回退到英文。
- `taf config language` 可以发现语言并显示当前选择；
  `taf config language en|zh|auto` 可以为 user/system scope 保存偏好；
  `TAFFISH_LANGUAGE` 可对单条命令临时覆盖。
- 高级用户可以提供稀疏外部语言包。无效或缺失条目会安全回退，不改变命令名、生成的
  shell、JSON schema、MCP protocol 数据、index 数据或其他机器接口。
- `taf` 和 `taffish` 顶层帮助提供简洁的命令/输入说明、示例、语言选择和官网、Hub、
  支持邮箱。编译器的容器设置位于示例前，并列出可选后端值。子命令帮助独立呈现，
  版本输出仍为单行。
- 安装后无需下载语言包即可使用内置英文和中文。GitHub/Gitee 来源选择不决定 CLI
  语言，普通重复安装保留已有语言偏好；独立安装脚本自身仍使用英文。

### 经过校验且支持事务回滚的二进制安装器

- GitHub 和 Gitee 安装器由同一个 canonical POSIX `sh` 模板生成，并由 CI 检查生成
  漂移、语法和 ShellCheck。
- 对官方 raw 下载，默认 `auto` 模式要求每个选中的二进制都匹配 `SHA256SUMS`。
  分离签名、发布公钥、`gpg` 和 `gpgv` 均可用时，还会按固定的 TAFFISH 公钥指纹
  验证清单签名。默认签名或公钥无法取得、或缺少任一工具时，安装记录的校验级别为
  `sha256`。签名或指纹校验失败则停止安装。
- archive 会在解包前检查路径和 entry type；下载具有有界重试和连接超时。
- 候选二进制先经过 `--version` smoke test，再在安装锁内事务替换三个核心命令。中断的
  commit 会恢复旧二进制和安装收据；完全相同的重复安装不会再次替换未变化的核心二进制。
- system 安装会把缺失的 Apptainer SIF 目录创建为管理员管理的 `0755`，并默认保留已有
  目录权限；只有显式 `--shared-sif-cache` 才会对准确的 SIF 目录设置并验证 sticky
  `1777`。
- `--dry-run` 不联网、不写文件；成功安装会在 `install-receipt.toml` 记录不含凭据的
  asset hash 和实际校验等级。

### 参数与内联调用修正

- CLI 空值不再触发 lexer 越界；缺少 option 值仍然报错。这不会为原始文本参数添加引用。
- 对于源码编译的 `<taffish>` 行，只有源码文本决定 `[[taf: ...]]` 的开始和结束。
  替换值中的引号或类似分隔符的数据不再改变调用边界；源码中的引号和转义可以保护 `]]`。
- 子命令编译失败的诊断独立进行 shell 引用，避免错误提示再次求值命令文本。
- `taf check/build` 共用源码边界扫描器发现依赖，不绑定参数、不运行 app。
  其他 emitter 和四种参数路径保留原有行为。

正确转发、展示、空值和延迟变量示例见
[参数替换、转发与展示](../standards/zh-CN/argument-passing.md)；实现边界和保留限制见
[emitter 设计说明](../dev/zh-CN/taffish-core/builtin-taffish.md#设计边界与取舍)。

### 可移植性与测试加固

- SBCL 和 LispWorks 的标准输入终端检测由 `han.host` 统一实现，使交付后的 `taf run`
  可以正确保留 pipe/file stdin，同时避免错误继承终端输入而阻塞。
- 外部测试会隔离 HOME、XDG、TAFFISH home、Git config、locale、临时目录和容器运行时
  变量。
- `taf check` 只拒绝脚手架的精确默认 smoke 占位值 `TODO` 和 `TODO --help`；包含
  `todo` 子串的合法命令名不会被误判。
- project/config 多行诊断改用 SBCL 和 LispWorks 均可移植的真实换行，不再依赖实现相关
  的转义假设。
- CLI 入口的错误处理覆盖 runtime I/O 和语言初始化。错误报告本身失败时仍以非零状态
  退出，包括 MCP stdio 模式在内，不使用 stdout 作为错误输出的备用通道。
- SBCL 的 SIGINT 使用简短诊断代替运行时回溯，保留退出码 1。LispWorks 保留 SIGINT
  时向 stdout 输出的固定 `Interrupted - quitting` 提示；全局信号处理器和 SIGTERM
  行为不变。这不保证从原生崩溃或资源耗尽中恢复，也不改变库函数的 condition 处理。
- 最终二进制测试覆盖 compiler、并发临时文件、project build/publish 恢复、Hub 包维护、
  doctor、多语言、长生命周期 MCP stdio session 和 CLI 错误边界。错误边界探测保留
  控制终端和超时保护，并使用只读描述符、断开的管道稳定测试写入失败。

## 兼容性

v0.11.0 保留既有命令接口；内联调用边界和 publish 策略的显式行为变化如下。

- 普通参数仍是原始文本；传入的 `@:` 参数块 token 继续逐个进行 POSIX shell 编码。
  `*ARGV*` 和 taf-app 命令模式仍按空格拼接 shell 文本。`"::*ARGV*::"` 保留拼接字符串
  的展示行为，不是 argv 原样转发；既有 shell 文本的延迟变量用法仍受支持。
  参数块 token 编码在 v0.10.1 中已经存在。
- 带源码信息的内联调用现在只从源码识别分隔符。在这条路径中，通过参数替换拼出完整的
  `[[taf: ...]]` 不再创建内联调用；应把分隔符写在源码中，只替换内部内容。
  仅提供 `:line/:number` 的旧 emitter 调用，包括动态 `<taf-app:taffish>` 命令模式，
  保留按文本扫描边界的行为。前缀校验、`--compile` 处理和子命令预编译时机不变。
- 内联调用仍限于单行；这不是完整 shell 解析器，也不会自动净化替换的 shell 文本。
  父子 flow 保留各参数路径的约定；子层使用原始文本时，仍可能丢失 argv 边界。
- 既有 `taf` 命令和 taf-app wrapper 调用方式继续有效；新的诊断和语言选项是增量能力。
- 机器可读 JSON key/value、MCP tools/resources/prompts/results、history/index/config
  数据、命令和 option token，以及外部进程输出不随语言变化。
- publish 仍然只支持 GitHub。GitHub/Gitee/自定义 source rewrite 继续用于 index 和安装
  路径，不会改变发布目标。
- publish 不再限制版本递增。`--pre` 现在创建真正的 GitHub prerelease，而不仅是绕过
  旧排序门槛。默认/`--latest` 会明确将新建正式 Release 标为 Latest；不应替换 Latest
  的维护版本请使用 `--no-latest`。已有 tag 身份仍受保护；安装仍消费 index 的
  `latest`，不会自行从 GitHub Release 渠道标记推导目标。
- 官方预编译平台仍然是 macOS Apple Silicon 和基于 glibc 的 Linux x86_64。

## 安装本版本

下列命令适用于所选来源的 v0.11.0 tag 载荷已可用之后。本次文档收尾未验证这些发布路径。

从 GitHub 固定安装 user scope：

```sh
curl -fsSL https://raw.githubusercontent.com/taffish/taffish/main/install/install-taffish.sh | sh -s -- --version 0.11.0 --user
```

从 Gitee 镜像固定安装 user scope：

```sh
curl -fsSL https://gitee.com/taffish-org/taffish/raw/main/install/install-taffish.gitee.sh | sh -s -- --version 0.11.0 --user
```

系统级安装、依赖、completion、Vim 集成、容器 backend、中国镜像和故障排查见
[README-CN](../../README-CN.md)。


```sh

```

要求清单可用，且选中二进制的哈希全部匹配。需要强制验证清单签名时，使用
`--verify gpg`。缺少分离签名、发布公钥、`gpg` 或 `gpgv`，或校验失败时，该模式会停止安装。

安装器。
